# Why pinned versions? RAG apps chain together many fast-moving libraries.
# Pinning means the app you build today still works the same way next month.
#
# WHY THE --extra-index-url LINE BELOW (CPU-only torch)
#   sentence-transformers (used for local embeddings and the cross-encoder
#   reranker) depends on torch. Installed with no other instruction, pip
#   resolves the default PyPI "torch" wheel, which pulls in a full CUDA
#   toolkit as separate "nvidia-*" packages (~4 GB) even on a machine with
#   no GPU -- this project only ever runs torch on CPU (a small local
#   embedding model and a small cross-encoder, neither GPU-accelerated
#   here). --extra-index-url adds PyTorch's own CPU-only wheel index
#   alongside PyPI; pinning torch to the exact "+cpu"-suffixed version below
#   is what actually makes pip pick the CPU build deterministically --
#   PyPI's default wheel never carries that "+cpu" local version suffix, so
#   only PyTorch's CPU index can satisfy this exact version string, with no
#   ambiguity about which index "wins". This cuts a full install from ~7 GB
#   to ~3 GB. If this exact pin 404s (this project's sandbox couldn't reach
#   download.pytorch.org to verify a "+cpu" build was published for this
#   specific torch version), check available versions with:
#     pip index versions torch --index-url https://download.pytorch.org/whl/cpu
#   and update both this pin and the sentence-transformers pin below to a
#   mutually compatible pair (any published "+cpu" version pair works --
#   this codebase only uses long-stable sentence-transformers APIs).
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.14.0+cpu
